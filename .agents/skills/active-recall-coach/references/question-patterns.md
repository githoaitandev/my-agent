# Question Patterns

Use these patterns to generate targeted questions. Prefer concrete questions over generic "explain more" prompts.

## Definition

- What does this term mean in your own words?
- What is the shortest correct definition?
- What is a common wrong definition?

## Mechanism

- What actually happens step by step?
- Which component owns this behavior?
- What input changes the output?
- Where is the boundary between these two responsibilities?

## First Principles

- What problem does this solve?
- What would happen if this did not exist?
- Why is this design necessary instead of accidental?

## Tradeoff

- What does this approach make easier?
- What does it make harder?
- When would you choose the opposite approach?
- Which decision is hard to reverse?

## Failure Mode

- How can this fail in production or local development?
- What symptom would you see first?
- What log, metric, test, or command would confirm it?
- How would you recover safely?

## New Member

- What background knowledge do I need before this makes sense?
- Which terms are team-specific?
- What should I try first if I get stuck?
- What mistake do new people usually make here?

## Critical Challenge

- What evidence supports that claim?
- Is that always true, or only under a specific condition?
- What is the counterexample?
- Which part of your explanation is hand-wavy?

## Scenario

- Given this situation, what would you do first?
- What would you check before changing code?
- What would you tell a new teammate?
- What changes if the system is 10x larger or the deadline is today?
